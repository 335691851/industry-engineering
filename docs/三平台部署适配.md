更新：2026-09-28。限定 Vercel、Supabase、Cloudflare，不需要独立 VPS。

## 当前完成范围

已实现业务云端适配代码，尚未部署到真实云账号。保留本地 SQLite 运行模式。

| 模块 | 实现 |
| --- | --- |
| 前端、CAD Studio | Vercel 静态站点，API 同域代理到 Worker |
| 登录 | Supabase Auth；后端交换令牌；HttpOnly Secure Cookie；写请求检查 Origin |
| 业务数据库 | Supabase Postgres，engineering 私有 schema，8 张业务/任务表，强制 RLS |

| 工程逻辑 | 保留 DeepAgents、专业工具、分阶段审核与人工确认后续跑 |

### 方案 A：不启用 Containers

Vercel Python 执行业务，Cloudflare Workflows 调度，Supabase 持久化。配置为 `deploy/cloudflare-platform/wrangler.functions.jsonc`。

**这是受限运行时，不等价于完整原生环境。** 不安装可选 RapidOCR/ONNX、build123d/OpenCascade，没有 ODA。OCR 需已配置的视觉能力或进一步验证原生依赖；不承诺 DWG 转换。Python PDF/DXF 库仍需实际通过 Vercel 包体和运行时限制验收。

单次函数配置上限 300 秒；Workflow 不会延长函数时限。目前按既有业务请求执行 Agent，尚未把所有模型/工具循环拆成独立 step。超时会保留已有成果并标记中断，不无限重放写操作。

### 方案 B：Cloudflare Containers 原生运行时

配置为 `deploy/cloudflare-platform/wrangler.jsonc`、`Dockerfile.cloud`。仍只用指定三平台，但需要 Cloudflare 账号启用 Containers 并承担费用。如果限制也禁止 Cloudflare Containers，只能选 A 并接受上述限制。

镜像安装 Python、RapidOCR/ONNX、build123d/OpenCascade、PDF/DXF 库及中文字体；构建时执行 `scripts/cloud_native_smoke.py`。本机没有 Docker，**尚未构建 Linux 镜像**；本机原生冒烟通过不能代替 Linux 验收。

DWG 需要有相应使用许可的 Linux ODA File Converter 加入镜像且在 PATH。代码支持 Unix 路径，但该二进制尚未安装与验收。不能复制 Windows exe 后声称云端可用。

## 调用链路与恢复

浏览器 → Vercel 同域 API → Cloudflare 网关 → Python 云端适配器 → Supabase 鉴权和业务数据。

长请求先写 cloud_tasks，再投递 Workflow。执行器通过 PostgreSQL 会话锁串行执行同用户同项目的任务，调用原 DeepAgents/工程工具；文件与结果写入 Supabase。人工审核后投递下一阶段。

- 状态：queued → running → completed/failed。
- 浏览器轮询及每 5 分钟的定时 outbox 扫描补投 queued 任务。
- Workflow ID 等于任务 ID；已完成任务重复调用不重复执行。
- 进程中断后丢失锁但任务仍为 running：标记失败，保留成果，要求检查后重新发起，避免重放不确定的写操作。
- 管理密钥仅在服务端，浏览器角色不能直接通过数据库 REST API 修改审核字段。

## 部署顺序

下面均未在云账号执行。命令默认在仓库根目录运行。

1. 选择 Supabase 项目，Auth 中创建测试用户，记录 UUID。按企业要求设置注册策略。
2. `supabase link --project-ref YOUR_REF`，然后 `supabase db push --dry-run` 检查并执行 `supabase db push`。完整业务迁移：`20260928005941_engineering_cloud_business.sql`；之前的校核任务迁移是独立功能。
3. `pip install -r requirements-cloud.txt`；服务端设置管理员 `SUPABASE_DB_URL`，执行 `python scripts/setup_cloud_checkpoints.py` 创建会话表和 RLS。不要在每次冷启动建表。
4. 连接必须使用直连或 **Session pooler**，配置 `sslmode=require`。不能使用 6543 Transaction pooler，租户变量和项目锁依赖连接生命周期。
5. 按 `deploy/cloud.env.example` 准备环境变量。数据库 URL、Supabase secret、模型密钥、服务令牌只能放服务端；服务令牌至少 32 字符、使用密码学随机数。不得使用 VITE_ 前缀公开密钥。
6. 在 `deploy/cloudflare-platform` 执行 `npm ci`。正式前端域名用于 `ENGINEERING_APP_ORIGIN`，必须和浏览器 HTTPS Origin 完全一致。
7. **方案 B**：填写 wrangler.jsonc 的 vars，`npx wrangler secret put NAME` 设置 SUPABASE_DB_URL、SUPABASE_SECRET_KEY、ENGINEERING_SERVICE_TOKEN、DEEPSEEK_API_KEY，然后 `npx wrangler deploy`。需要本机或 CI 的 Docker，构建 linux/amd64 镜像。
8. **方案 A**：先将下述 vercel-python 产物部署为单独 Vercel 项目，设置 cloud.env 中的服务端环境变量。把正式 URL 填入 wrangler.functions.jsonc 的 PYTHON_BACKEND_URL；用 `npx wrangler secret put ENGINEERING_SERVICE_TOKEN --config wrangler.functions.jsonc` 设置同一令牌，然后 `npx wrangler deploy --config wrangler.functions.jsonc`。Deployment Protection 若启用，需要额外配置受控访问；当前代码不自动绕过保护。
9. `npm run build`；`python scripts/package_cloud_platform.py --backend https://YOUR-WORKER.workers.dev`。输出 `.cloud-build/platform-时间/frontend` 与 `vercel-python`。frontend 作为 Vercel 静态项目部署，配置已含 API 代理。可先确定两个项目的正式域名再完成循环引用配置。
10. 验收上传、MBOM、审核、图纸、工艺、归档，并测试刷新、重新登录和运行时重启。用第二个账号验证无法读取第一个账号的数据、文件和会话。

打包只复制前端产物、后端源码与依赖，不复制本机数据库、样例、日志或 .env。独立视觉服务如需启用，须显式传入对应环境变量，不能假定本机配置会上传。

## 旧数据迁移

备份 SQLite 与 files 后先只读预检：

```powershell
python scripts/migrate_cloud_data.py --owner SUPABASE_USER_UUID
```

核对归属和计数后增加 `--apply`。可用 `--sqlite` 指定源库。脚本不删除源数据、不覆盖云端同 ID 数据；数据库失败回滚，但已上传对象可能需要清理。旧运行中任务按中断处理。

迁移业务消息与工程记忆，不迁移旧 SQLite checkpoint 中未完成的工具调用。新云端会话在无 checkpoint 时加载近期业务消息，避免历史工具重放。旧 CAD 临时编辑会话不作迁移保证；已保存到业务记录的成果可迁移。
