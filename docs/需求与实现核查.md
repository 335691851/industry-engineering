# 智能工程解析平台：需求与实现核查

本次核查日期：2026-09-23。此文描述本次代码实际完成的调整，并区分产品目标与当前能力边界。

## 1. 产品需求重新梳理

目标是让制造工程师与 Agent 协作，把装配 PDF 转成可追溯、可编辑、可审核的工程成果。

| 阶段 | 输入 | Agent 工作 | 用户工作 | 下一阶段输入 |
|---|---|---|---|---|
| 装配解析 / MBOM | 装配 PDF、图号、历史方案 | 识别制造边界、多级关系、每上级用量、复用与不确定项 | 编辑结构并审核 | 已确认的零件定义与装配使用关系 |
| 参考输入 | 当前对象、库内相似图、补充上传 | 搜索候选并解释适用范围 | 选图；或确认无参考图继续 | 明确选择的参考图与装配接口证据 |
| 制造图与放量 | 当前参数、已审核参考输入、下级交付成果 | 识别本件成品边界、结构、尺寸、制造交付状态、毛坯与留量建议 | 编辑、预览、复核并审核 | 已审核成品图和制造方案 |
| 核心工艺路线 | 已审核图纸、放量、交付状态 | 从毛坯到本件合格交付的加工 / 装配和检验路径 | 修改工序并审核 | 当前对象完整成果，可供上级使用 |
| 归档 | 所有必需阶段已审核 | 提供成果与状态 | 保存到零件管理 | 可复用的工程资源 |

下级先完成，上级再生成。单件图不含兄弟件；组件图可以表达它的已审核下级与接口。每阶段先形成草案，经人工审核后才作为下一阶段输入。放量是工艺建议，不能与成品尺寸或尺寸公差混用。

交互采用两种共同入口：固定步骤按钮负责明确操作；对话 Agent 处理查询、解释、参数修改、MBOM 修订、相似图检索、留量试算和专业生成。两者调用同样的阶段校验，Agent 不具备人工审核工具。

## 2. 查出的根因与本次修复

| 原问题 | 后果 | 现实现 |
|---|---|---|
| 缺失零件几何补入 140/60/20 等固定样例值 | 产生无证据制造尺寸 | 删除固定补值、均分未知段、按总长比例缩放与凭差值增加新段；仅求解一个已定位未知段 |
| 任何非回转体被当成圆板 | 支架 / 箱体变成错误实体 | 未支持形状返回 unsupported，保留待建模项 |
| 辊筒内孔可能由小轴径猜出 | 对象边界错误 | 禁止将轴段直径转换成筒体内孔；非 tube 轮廓不能沿用装配总长 |
| 相似图审核后仍自动读取其他历史图 | 输入与用户审核不一致 | 制图只读取实际审核选择的 source_pdf；无参考图不暗中使用历史候选 |
| 子件改变后上级审核保留 | 上层工艺继续消费过时数据 | 沿全部父子使用关系递归失效，覆盖复用件的多个父节点和根装配工艺 |
| 材料 / 图号修改不撤销图纸审核 | 审核内容与当前参数不同 | 属性变化撤销图纸及工艺审核；清除下游当前文件链接 |
| 旧批量函数直接顺序调用模型 | 存在绕过 Agent 与阶段门的路径 | 移除旧 run_generation；统一专业 Agent 和工作流编排 |
| 重新生成工艺只是保存表单 | 按钮行为与名称不符 | 区分保存工序编辑与专业 Agent 重新规划 |
| SVG / PDF / DXF 独立布局 | 预览与导出不一致、PDF 盘类件缺图 | 统一毫米绘图场景；同一组几何 / 标注 / 注释生成 SVG、PDF 和 DXF 图纸布局 |
| 技术要求截断、无统一分页 | 丢失制造信息 | 按字宽换行并续页；所有注释完整进入各输出 |
| 图纸导出覆盖固定文件 | 并发或重生成污染旧结果 | 每次导出使用版本目录；提交前检查输入更新时间 |

## 3. 制造放量模型

成品尺寸仍保存在 geometry。制造方案单独保存在 geometry.manufacturing：

- delivery_state：本件作为成品的交付状态，明确是否还需由上层总成完成后加工。
- blank_type：毛坯类型。
- core_route：用于解释留量的核心工艺路径。
- allowances：留量要素的数组。

每个留量要素包含 dimension（成品尺寸字段路径）、kind（external / bore / axial）、per_side_mm（单边余量）、faces（加工面数）、basis（依据）、reason（材料 / 毛坯 / 工序理由）。finished_mm、blank_mm、calculation、error 由服务器重算，不信任模型或客户端提交的计算结果。

外径毛坯尺寸 = 成品外径 + 2 × 单边余量；内孔毛坯尺寸 = 成品孔径 − 2 × 单边余量；轴向毛坯长度 = 成品长度 + 加工端面数 × 单边余量。内孔结果不能为负。空值、非有限数、错方向、缺依据和理由都进入审核阻断。

Agent 可依据当前工程证据提出合理的工艺建议，不要求用户先填写全部参数。建议必须带适用前提并经人工审核。系统没有把任意固定余量数字伪装成 ISO 规定值，也没有建立完整的行业余量数值数据库。

编辑抽屉分别展示成品尺寸、制造方案与放量、技术特征。已保存的手工改动记录于 user_overrides，再生成时优先保留；通过对话精确改尺寸也先走相同参数保存服务。

## 4. Agent 与系统调用链

```text
固定生成按钮 → /api/parts/{id}/generate/{drawing|process}
自然语言 → /api/chat → DeepAgents 工程会话 Agent
                         ↓ 受控工具
                专业制图 / 工艺 Agent
                         ↓
    统一阶段门 → DeepSeek 结构化草案 → 几何 / 留量 / 工艺校验
                         ↓
       版本文件导出 → 输入变更检查 → 更新当前成果 → 人工审核

批量操作 → 工作流编排 Agent → 当前已解锁的专业 Agent → 等待人工审核
```

会话工具现有：inspect_project、search_engineering_memory、generate_part_drawing、generate_part_process、generate_assembly_process、inspect_current_stage、update_part_parameters、calculate_machining_allowance、search_similar_part_drawings、revise_mbom_part。参数工具无法写审核状态。MBOM 修订会回到结构待审核。复用件的具体关系编辑仍在 MBOM 表格中选择目标关系。

会话检查点使用 SQLite；工程事实与成果以业务数据库为准。通过 user_overrides 保存用户参数，防止重复生成时丢失。专业 Agent 目前每次按任务调用，未实现独立持久化的复杂 CAD 推理状态。

## 5. 标准与图纸实现边界

ISO 128-1:2020 仍是制图表达的主参考，相关线型、视图、尺寸、比例和图幅标准集中于 drawing_standard.py。本实现是可测试的制图配置，不等于已经逐条通过完整标准的符合性认证。

当前可绘制：直筒 / 环筒纵向剖视与端视、圆盘 / 环板、阶梯轴主视与分段尺寸。SVG 与 PDF 图框、注释、留量表来自相同绘图场景；DXF 的 A3-* 布局包含同一图纸场景，模型空间保留 1:1 外形和基础原生尺寸，DWG 由 ODA 转换。

尚未完成：任意三维 CAD 建模、多孔系、螺纹实体、复杂焊缝和完整形位符号的自动表达；子装配的任意空间几何求解；受控标准全文与企业制造能力数据库；标准件/采购件专用免重绘流程；企业身份审签、不可变工程版本谱系及 PLM/ERP 对接。不能把当前系统宣传成已经能从任意装配图自动产生完整可投产图纸。

复杂零件的需求仍然有效。下一阶段应引入参数化 CAD 内核、结构化特征建模与独立制造规则库，而不是继续增加按零件名称猜尺寸的模板。

## 6. 验证

新增测试覆盖留量方向与来源、缺失尺寸、共享子件依赖失效、审核绕过、对话参数修改、导出内容与分页一致性。原有端到端测试保留上传、MBOM、多级流程、文件导出和归档，并将旧的“凭差值制造新段”样例改成“已定位段的单个长度缺失”。

本次集成测试使用受控模型返回，验证系统执行逻辑；它不能替代真实工业图纸语义识别准确率评测。PDF 测试样例已实际渲染检查。

本轮结果：13 项测试通过，TypeScript / Vite 构建通过。新增重复审核的幂等性测试，确认不会清除已审核的后续工艺；审核后的图纸和工艺导出使用新版本并显示审核状态。浏览器自动化因本机浏览器无法启动及 Chromium 下载失败未完成，不能据此宣称已经完成页面交互验收。
